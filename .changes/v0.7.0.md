## 0.7.0 - 2026-10-06

### Added

* Show the cause of a failed conversion, e.g. the file system error or the
  malformed value, and keep it accessible in `ParseError.Err` for `errors.Is` and
  `errors.As`
* Batch convert converts an input file again and replaces its output file if the
  input file is newer than the output file, e.g. after downloading it again, and
  reports it as "Updated"

### Changed

* Rename `parser.ParserError` to `parser.ParseError`, `parser.ParserErrorType` to
  `parser.ErrorType` and the field `ErrorType` to `Type` to follow the Go naming
  conventions
* Reject unknown keys in the config file, e.g. a misspelled `inputDir` instead of
  `inputdir`, instead of silently ignoring them. Config files with such keys have
  to be corrected
* Build the release binaries with `-trimpath`, so that they do not contain file
  system paths of the build machine

### Fixed

* Return a non zero exit code from `batch-convert` when a file fails to convert
* Do not leave an incomplete output file behind when writing fails, e.g. on a full
  disk, so that `batch-convert` does not skip the input file in later runs
* Remove the temporary files of the Barclaycard parser after parsing large Excel
  files
* Print error messages to stderr instead of stdout
* Do not convert input files in `batch-convert` which would be converted to the
  same output file, e.g. `Umsaetze.csv` and `Umsaetze.xlsx`, but report them as
  failed instead of silently skipping or overwriting one of them
* Do not fail to write an output file when a temporary file of an aborted earlier
  run is left next to it. The temporary file now gets a unique name, which also
  makes new output files accessible by the current user only
* Ignore subdirectories of the input directory in `batch-convert` instead of
  reporting them as failed files

### Security

* Build releases with the latest Go patch release instead of the latest stable Go
  version, and check the code and its dependencies for known vulnerabilities with
  govulncheck
* Reference the GitHub Actions of the CI and release workflows by commit SHA
  instead of by tag, so that a moved tag cannot run different code
